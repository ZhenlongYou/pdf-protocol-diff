1. 工具用途与界面结构

文件对比工具用于比较两份 PDF 的版本差异。它先识别章节和正文，再补充表格截图、Figure 原图和视觉漏检证据，最后生成适合人工审阅的 HTML 报告以及 CSV、JSON 等审计文件。

关于“页签”：当前桌面版没有传统的多页签界面。软件由一个主工作页和一个“高级设置”弹窗组成；比较完成后，HTML 报告在系统浏览器中作为独立页面打开。主界面中的“旧版 PDF”和“新版 PDF”是两张输入卡片，不是页签。

工具关注的是技术文档审阅：正文按逻辑章节匹配，不强制把旧版第 N 页和新版第 N 页直接配对。因此，即使新版插入内容导致后续页码整体移动，同一章节仍有机会正确对应。

自动结果用于定位和筛查，不能替代对源 PDF 的最终确认。尤其是公式、复杂多栏、扫描件和图形语义，需要结合报告给出的可信度与原文证据判断。

2. 三分钟快速上手

选择旧版 PDF。点击左侧“选择旧版 PDF”区域，选中作为比较基准的旧文件。
选择新版 PDF。点击右侧“选择新版 PDF”区域，选中要审阅的新文件。
确认页面范围。通常保持“全部页面”；只审阅某段内容时，再分别为旧、新 PDF 选择起止页。
按需调整高级设置。第一次使用建议保持阈值 0.72、每章片段数 20。
点击“开始比较”。等待状态栏依次显示读取、匹配、生成视觉证据和生成报告。
打开 HTML 报告。先看顶部“识别可信度”，再按左侧导航核对表格、正文和视觉复核项。

4. 页面范围怎么选

选择方式含义适用场景
全部页面从第一页比较到最后一页。正式版本审阅、第一次比较、需要完整结论时。
选择页面起始页和终止页都包含在范围内，页码从 1 开始。只审阅某个 Annex、章节或已知修改页段时。

旧、新 PDF 的页窗相互独立。例如旧版目标内容在第 20–30 页，新版插入了两页后位于第 22–32 页，可以分别输入这两个范围。

双侧页窗具有更强的“相关范围”含义。当旧、新两侧都完整填写页窗时，工具仍优先使用章节结构和正文证据，但也会把这两个范围视为用户明确声明的相关区域，帮助恢复因大幅改写而难以自动配对的章节。不要为了缩短时间而随意指定互不相关的两段页面。

选择“选择页面”后，起始页和终止页必须全部填写，且都应为不小于 1 的整数；起始页不能大于终止页。

6. 章节匹配阈值有什么用

章节匹配阈值不是“差异灵敏度”。它主要用于判断两个标题已改名、编号已变化的章节是否仍可能是同一个逻辑章节。正文中的数值、单位、否定词、标识符等细微变化不会因为把阈值调低就自动消失。

设置倾向可能结果典型现象
较低章节配对更积极。可能减少“整章新增 + 整章删除”，但也增加把两个相似模板章节配错的风险。
默认 0.72在当前工具中作为日常折中值。适合大多数有稳定章节结构的协议 PDF。
较高章节配对更谨慎。可减少误配，但大幅改写或改名章节更容易被拆成新增和删除。

可输入范围为大于 0 且不超过 1 的有限数字。若报告中大量本应对应的章节被拆成“新增/删除”，可以小幅降低后复跑；若两个明显无关章节被放在同一张修改卡中，可以小幅提高后复跑。

不要只看相似度数字。同编号、父子章节关系、相邻章节和用户指定页窗等强结构证据，也可能成为配对依据。报告在相关卡片中会显示“配对依据”，供人工判断。

7. 每章片段数有什么用

“每章片段数”控制每个章节在读者报告里最多展开多少条正文差异候选。新增、删除和替换三类合计占用这个额度；它不是整份 HTML 的总上限，也不限制章节匹配和完整比较。

示例HTML 中看到什么完整数据在哪里
某章共 12 条，设置 20显示全部 12 条。HTML、CSV、JSON 都有。
某章共 35 条，设置 20展开优先级较高的 20 条，并提示“还有 15 处未展示”。changes.csv 和 protocol_diff_data.json 保留完整审计片段。
设置 0正文差异片段不展开，只显示未展示数量和其他报告证据。完整审计内容仍在 CSV/JSON。
未展示内容不能在当前 HTML 中展开。HTML 只告诉你未展示了多少条，不提供“展开剩余 15 条”的按钮。若希望继续在 HTML 中阅读，需要把“每章片段数”调大并重新生成报告；也可以直接查看 changes.csv 或 JSON。

该上限针对正文差异片段。表格卡、Figure 原图、视觉漏检核对项和各章节本身有独立的报告结构，不会简单地被这个数字截成整份报告只剩 20 项。

点击“开始比较”后，软件先校验两个 PDF、输出目录、页面范围和高级参数。校验通过才会开始后台处理。状态栏会显示预扫描、读取、构建章节、章节匹配和报告生成等阶段。预扫描与读取显示页数；匹配显示已检查候选数或章节数。这些计数属于当前阶段，不是整项任务的完成百分比。

运行期间，“开始比较”变为“比较中”，并显示已用时间，同时出现“终止比较”按钮。点击后显示“正在停止”，结束本次后台任务、清理本次临时文件，再恢复“开始比较”。其他按钮和输入框暂时禁用；关闭窗口也会先终止任务，清理完成后再关闭。只有完整报告才会出现在输出目录，取消不会覆盖或删除以前的报告。

成功后，状态栏显示可信度及主要数量，并出现“打开 HTML 报告”和“打开输出目录”。如果处理失败，错误原因会直接显示在底部状态区域，输入控件恢复可用。

9.1 顶部识别可信度

状态应如何理解
可靠两份文档符合当前支持范围，并且要求的视觉漏检核对已完整执行。只有这一状态才允许在支持范围内使用“未检出差异”的结论；公式本体仍不在自动判等范围内。
需人工复核报告仍保留已识别的正文、表格和视觉证据，但存在版面、OCR、抽取或配对风险。即使数量为 0，也不能据此确认两份文件一致。
无法判断至少一侧缺少足够的可比较文字或章节。常见于扫描件没有可用 OCR、页面不可读或抽取失败。

9.2 汇总指标

指标含义
核心技术变化读者报告中保留的技术正文新增、删除或修改章节数。
正文字符复核项字符映射、结构顺延等不宜自动下结论、需要人工确认的正文项。
公式自动对比（已关闭）始终为 0。公式区域只用于版面隔离，不输出公式增删、修改或相似度结论。
视觉漏检核对文字层未解释、但源页面像素仍出现变化的人工复核页数。
变化表格报告中有变化或需要复核的表格卡数量。
表格行变化结构化表格中识别出的实质行级变化数量。
表格复核项行归属、字体编码或结构证据不足，不能自动认证的表格项。

9.3 左侧导航“入口”

左侧项目是页内跳转链接，不是筛选页签。点击后，浏览器会滚动到对应证据卡：

  • 表格补充证据：以 T1、T2……编号，跳到变化表格卡。
  • 技术正文变化与复核：跳到具体章节卡，卡片标明修改、新增、删除或复核。
  • 视觉漏检核对：跳到 V1、V2……页面级视觉证据。

9.4 报告元信息

报告会列出旧、新 PDF 路径、源文件页数、实际选择页、比较方式、报告范围和使用提示。先核对这些信息，可以避免把选错文件或选错页窗误认为算法问题。

9.5 技术正文变化卡

  • 卡片标题：显示变化类型和章节位置。
  • 定位信息：显示旧版页、新版页及章节相似度。
  • 配对依据：在使用结构证据或用户页窗锚定时，说明为何把两章视为对应章节。
  • 差异摘要：概括替换、新增、删除和未展示数量。
  • 旧/新版原文区域：优先并排显示源 PDF 裁剪，旧版变化词淡红、新版变化词淡绿；相同文字不着色。
  • “查看文字识别明细”：这是可点击的折叠项。展开后查看结构化文字片段；再次点击可收起。
  • 未展示提示：只显示剩余数量，不能在当前 HTML 中继续展开。

9.6 表格补充证据

表格卡并排显示旧、新表格截图，并列出表题、页码、配对相似度和行级变化。表格行可能标记为修改、新增、删除或“需人工复核”。长单元格可能以折叠明细呈现，点击摘要可查看完整值。

9.7 Figure 原图核对

Figure 按图题和文档顺序配对，只并排展示旧、新原图，不对图内文字和技术含义自动标色或解释。单侧 Figure 或图题配对不确定时，应直接回到源 PDF 核对。

9.8 视觉漏检核对

当可抽取文字没有解释页面中的图片、印章或普通矢量图变化时，报告可能给出旧页、新页和差异掩膜。该卡的作用是阻止“文字相同就一定相同”的假结论；它不负责判断图形变化代表什么技术含义。

HTML 报告当前没有：全文搜索框、筛选按钮、导出按钮、展开全部按钮，以及展开“未展示片段”的按钮。全文搜索可使用浏览器的 ⌘ + F（macOS）或 Ctrl + F（Windows）；导出和完整审计请使用同目录下的 CSV/JSON。

10. 六种输出文件

每次运行都会在输出目录下创建一个形如 protocol_diff_YYYYMMDD_HHMMSS 的新文件夹，不覆盖之前的报告。

protocol_diff_report.html
主要阅读报告

包含导航、可信度、原文截图、正文差异、表格证据和视觉复核项，适合浏览器阅读。

protocol_diff_report.md
Markdown 报告

适合放入文档系统、Wiki 或代码仓库，内容以文字证据为主。

protocol_diff_report.txt
纯文本报告

适合复制到邮件、聊天或不支持 Markdown 的系统。

changes.csv
正文审计表

每行对应一个章节变化，保存完整新增、删除和替换片段；可用 Excel 筛选。

table_changes.csv
表格变化表

保存表题、页码、配对分数、项目名、旧值、新值和行变化类型。

protocol_diff_data.json
完整机器审计数据

同时保存原始审计事实和读者显示投影，包括完整正文片段、表格、视觉项、章节、抽取状态和来源信息。

保密提醒：报告可能包含源 PDF 路径、文字片段、表格内容和内嵌截图。保存、传输和共享报告时，应按原 PDF 的保密级别处理。

11. 如何判断结果

  1. 先看可信度，后看数量。“需人工复核 / 0 项”不等于两份文件一致。
  2. 确认输入和页窗。核对报告中的旧、新路径与选择页。
  3. 先看表格和视觉证据。这些区域位于报告正文之前，通常更容易暴露数值或图形变化。
  4. 按左侧导航逐章复核。旧版淡红代表被删除或替换的旧内容，新版淡绿代表新增或替换后的新内容。
  5. 看到“未展示”时不要停止。根据任务需要调大片段数复跑，或转到 CSV/JSON 查看完整审计内容。
  6. 最终回到源 PDF。页码和截图是定位工具；规范性结论仍应以源文件为准。

常见变化类型

类型含义
修改旧、新章节已配对，正文中存在替换、新增或删除。
新增新版出现了未找到对应旧章节的内容。
删除旧版内容在新版中没有找到对应章节。
复核存在字符映射、布局顺序或结构证据不充分的问题，工具不自动认定为实质技术修改。
未变化只有开启“列出未变化章节”时才会列出；默认隐藏以缩短报告。

12. 支持范围与限制

当前较适合的文档

  • 具有可选择文字层的 PDF；
  • 阅读顺序较稳定、章节编号或标题较清晰的协议与技术规范；
  • 具有清晰表格边界，或至少能稳定抽取结构化行的表格；
  • 需要按章节定位正文变化、按行核对表格变化的版本审阅任务。

必须谨慎的情况

  • 扫描件：只有检测到图像主导页面且系统安装 Tesseract 时才会尝试 OCR；OCR 成功的比较仍至少标为“需人工复核”。
  • 复杂多栏和表单：阅读顺序可能与视觉顺序不一致，工具会保守降级。
  • 公式：自动公式差分已关闭。分式、根号、上下标和式号只用于版面隔离。
  • Figure：只并排提供原图，不解释图内标签和技术语义。
  • 无框或复杂跨页表格：可能退回普通正文，或显示“需人工复核”。
  • 页眉页脚和水印：只有坐标证据足够时才过滤；证据不足时宁可保留复核噪声，也不删除未知技术内容。

14. 常见问题

设置每章 20，整份 HTML 是否只能看到 20 条？
不是。20 是每个章节的正文差异展开上限。不同章节各自计算，表格、Figure 和视觉核对项也有独立结构。
某章有 35 条差异，剩余 15 条能在 HTML 中展开吗？
不能。HTML 只显示“还有 15 处未展示”。把每章片段数调大后重新生成，或查看 changes.csv / protocol_diff_data.json。
阈值调低会不会漏掉细小文字变化？
章节匹配阈值主要决定两个章节是否配成一对，不是正文差异过滤阈值。技术数值、单位、否定词和标识符变化仍会参与比较。
为什么旧、新页面范围可以不一样？
新版本插入或删除页面后，同一章节的物理页码会移动。两侧独立页窗可以让你准确指定各自的目标区域。
为什么报告显示 0 项，却仍写“需人工复核”？
0 只表示当前支持的抽取层没有检出读者差异；如果扫描、版面、OCR、视觉覆盖或章节识别存在风险，就不能据此确认一致。
报告是否自动比较公式？
不比较。公式自动差分已关闭，公式区域只用于避免正文或表格重复识别。复杂公式必须回到源 PDF 人工核对。
运行很慢怎么办？
先确认是否选了整份长文档、是否包含大量扫描页或表格。只审阅明确章节时可选择合理页窗；不要为了提速把两侧指定成不相关范围。可点击“终止比较”停止当前任务，再调整页窗重新开始。每次表格 OCR 最多等待 60 秒；超时会保留识别失败说明和已有证据，不会当作内容没有变化。
怎样在 HTML 中查某个参数名？
使用浏览器自带的页面查找：macOS 按 ⌘ + F，Windows 按 Ctrl + F。
