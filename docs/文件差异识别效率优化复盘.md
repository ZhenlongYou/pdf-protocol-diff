# 文件对比工具的识别效率是怎样提高的

## 结论

这次改造覆盖了“PDF 抽取→结构识别→新旧配对→差异判定→报告呈现”整条链路，单独调整一个 OCR 参数无法解决这类问题。旧方案把 PDF 中抽出的字符序列过早当成文档语义，导致页眉页脚、表格、图注、公式和正文相互污染；同时，章节和表格的配对过度依赖编号与位置，一处插入就可能引发后续内容连锁错配。

最终采用的思路是：保留页码、坐标、来源引擎和原始文本这些可追溯证据，用多个独立证据为“这是同一个对象”授权；证据不足时保留新增/删除或“需人工复核”，不让相似度阈值代替技术判断。完整处理链现在是：

`PDF 快照与坐标证据 → 逐页路由/OCR → 章节、表格、图和正文分层 → 保守配对 → 视觉漏检兜底 → 读者报告 + 完整审计数据 → 真实样本验收`

## “识别效率”在这个项目中的含义

本文中的识别效率，主要指单次运行后能被正确找到、正确归属、并能被人有效复核的差异比例。它包含三个方面：

- 少漏检：工程数值、单位、正负号、大小写标识符和表格行变化不被“差不多”的文字吞掉。
- 少误报：页眉页脚、修订历史、定位引用编号、图内标签和已由表格卡承载的文字，不再反复冒充技术正文变化。
- 少人工搜索：报告中的差异有旧/新位置、原文截图和结构化行证据，读者不需要在两份 PDF 中手工翻页重建上下文。

目前没有一组条件严格一致的整机前后耗时数据，因此不应把这次改造表述为“运行速度提高了多少倍”。对运行时间可以确认的改善是：原生文字仍是默认快速路径，重型版面后端只在用户显式选择且页面已显示阅读顺序风险时才参与；图形界面在后台执行比对并显示真实阶段与页数，减少了“点击后卡死”的感受。[抽取入口与快速路径](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/pdf_extract.py#L138-L190)、[完整流水线与进度事件](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/compare.py#L127-L207)

## 旧方案为什么显得“识别低效”

| 现象 | 根因 | 实际后果 |
|---|---|---|
| 封面、版权、页眉页脚和修订历史位于报告前部 | 线性文字抽取缺少稳定的页面坐标与区域归属 | 真实技术变化被噪声淹没 |
| 章节编号整体顺延后，一个新增变成多个修改 | “同编号/同标题”被过早当作同一对象 | 后续章节连锁错配 |
| 一张表删掉一行后，后续多行全部错位 | 依赖页码、表号或行序，缺少表族和行身份证据 | 产生大量伪修改和伪新增/删除 |
| Figure 里的短标签被当成表格或正文 | 抽取结果没有明确的 Table/Figure/Formula/prose 所有权 | 同一物理区域在多处重复报告 |
| 报告显示“没有差异”，但页面图形可能已改 | 文字层一致被误当成整页一致 | 形成最危险的假绿结论 |

这些问题不能靠全局降低相似度阈值解决。阈值放宽会让更多对象被配上，但也会同时增加错配；只在报告端隐藏噪声也不够，因为错误已经在上游改变了章节和表格的身份。

## 解决方法

### 1. 先把 PDF 变成可追溯证据，再做语义比较

抽取层不再只返回一大段文字。每个页面块都保留物理页码、边界框、阅读顺序、来源引擎和逐词坐标，并把来源分成原生文字、表格与 OCR 三类。这使后续模块可以回答“这句话来自哪一页、哪一块、是否经过 OCR”，而不是只看一个字符串。[证据块数据模型](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/models.py#L24-L95)

页面还会根据实际事实标记为原生文字、原生版面风险、OCR 回退、图像主导但有文字层，或不可读图像。OCR 只对大面积栅格图且原生文字不足的页面尝试；即使 OCR 成功，也只能作为降级定位证据，不会被包装成可自动判等的原生文本。[逐页解析路由](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/models.py#L31-L66)、[扫描页 OCR 回退](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/page_ocr.py#L31-L120)

页眉、页脚和页边打印行号也改为“有坐标证据才过滤”。例如运行页眉需要跨多页的稳定位置和重复证据；某页上看起来像标题的技术内容不会因一个字符串规则就被删除。这是报告降噪能够不伤及正文的前提。[识别率一期的坐标过滤验收记录](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/86e1a26e6cc7c20abf7905fbddd3935ce6e41165/handoff.md#L21-L30)

### 2. 章节配对从“编号优先”改为“身份证据优先”

新旧两份文档中，章节编号和标题只是候选身份，不是硬性对应。即使编号和标题一致，双方实际正文仍需达到用户设定的最低相似度；如果不足，该对象会进入全局候选配对，或保留为新增/删除。全局候选按证据强度排序后再消费，避免文档顺序中第一个“看起来像”的候选抢走正确对象。[章节配对实现](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/compare.py#L2068-L2200)

对数值、限值、正负号、单位、大小写技术标识符和赋值表达，匹配层不再使用普通自然语言的宽松等价。只有可证明的定位编号顺延、排版断词或符号字体差异才会在读者层中和，真实工程 token 必须保留。这一边界在一期验收中专门保护了 `mV/MV`、`UI/ui`、`CMIT-LT/CMIS-LT` 等用例。[技术 token 边界验收](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/86e1a26e6cc7c20abf7905fbddd3935ce6e41165/handoff.md#L23-L29)

### 3. 表格从“按页码/表号对齐”改为“表族、锚点和行身份联合证明”

协议版本升级时，整组表可能从 Clause 29 移到 Clause 30，中间还可能插入一张新表。新方案要求表族中存在多个全局唯一、完整且单调的描述性标题锚点，并且不存在拆分/合并竞争，才允许建立跨 Clause 对应。两个锚点之间的编号偏移如果不一致，该区间直接保留新增/删除，不依赖表号猜配。[跨 Clause 表族配对实现](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/reporting.py#L2695-L2781)

表内不再默认“同一位置就是同一行”。实现会结合 Parameter、Symbol、数字身份、重复 occurrence、列顺序和完整性证据；缺格、重叠框、跨行争抢、乱序字符或非有限坐标会使行对齐失去可靠资格，而不是让报告继续给出一个整齐但错误的变化列表。这一修复在真实 112G/224G 文档对上将 13 张旧表映射到正确新表，并保留 `Table 30-12` 为唯一技术新增；TP1a 删除一行后，SDC22、SCC22、ERL、Transition Time 和 NOTES 不再连锁错位。[表格修复与真实语料验收](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/5c4c8b3694e1c1b2e2a244ad2635d0e8ccbf8d08/handoff.md#L12-L33)

### 4. 不允许文字层的“无差异”直接升级为整页一致

完成文字、表格和公式比较后，系统还会对可安全配对的页面做低分辨率像素层核对。已经由页眉页脚、表格或公式证据解释的区域会被扣除；剩余像素如果仍发生变化，报告只追加“视觉漏检复核”证据，不会猜测它的技术语义。如果像素核对未完成、页面无法安全对齐，或存在未解释视觉变化，整体状态会被阻止为 all-clear。[视觉哨兵与失败关闭](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/compare.py#L165-L225)

这一层不是“图片内容自动理解”。它的职责是防止假一致：在无法解释图形变化时，把证据交给人工复核，而不是用一个看似确定的句子遮住能力边界。

### 5. 将“完整审计数据”与“人类可读报告”分开

一份好的差异报告不应把所有中间结果都铺给读者，但也不能为了简洁丢失审计事实。现在 JSON/CSV 保留原始新增、删除、替换、位置和省略计数；同一条记录另外生成 `display_*` 投影，专供 HTML/Markdown/TXT 呈现已证明可以降噪的结果。[审计字段与读者投影](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/reporting.py#L12993-L13045)

同时，Table、Figure、Formula 和 prose 采用互斥的视觉归属。已经属于表格的区域不再被长正文截图重复着色；纯 Figure 图注和图内标签不再冒充正文变化；没有坐标证据时则保守保留，不会根据关键词盲删。[原文截图证据入口](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/prose_source_visuals.py#L110-L179)、[视觉归属实测记录](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/c4dbf83d2ad020eb85c7ff6251bbca668e76b84c/handoff.md#L12-L40)

### 6. 把“不知道”做成正式结果

只给一个差异数量很容易产生误导。现在系统同时评估文字量、稳定章节数、回退文本块、抽取告警、OCR 页、图像主导页、阅读顺序风险、空白页比例和表格完整性，再输出三种可靠性状态：

- `reliable`：在当前支持范围内，才允许得出“未检出受支持差异”。
- `degraded`：差异证据仍可用，但零变化不能证明一致。
- `indeterminate`：至少一侧缺少可比较文字或章节，无法判断。

评估只改变结论资格，不会篡改已抽取或已比较的事实。这个设计直接消除了“复杂 PDF 一条都没识别到，因此两份文档完全一致”的假绿路径。[可靠性评估实现](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/quality.py#L192-L330)

## 如何证明确实解决了问题

验收不使用“编写这套规则的人认为结果正确”作为唯一依据，而是同时使用受控 PDF、真实 OIF 版本对、Gold 事件、最终 HTML/JSON/CSV 和源 PDF 截图。Gold 验收按具体的正文、表格、公式和视觉事件匹配，并分别检查 HTML、Markdown 和 TXT 是否按预期可见；对 occurrence 数量和技术 token 边界也有独立约束。[Gold 验收入口](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/accuracy_evaluation.py#L69-L145)、[事件与读者面匹配](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/cc0fc128514c9b4989b432c186685aba44ab326f/src/protocol_pdf_diff/accuracy_evaluation.py#L732-L811)

以三个关键阶段的验收为例：

| 阶段 | 真实问题 | 可观察结果 | 证据边界 |
|---|---|---|---|
| 2026-08-10 识别率一期 | OIF 532 中定位引用噪声、工程 token 和视觉漏检风险 | 语义 Gold `2/2` 事件命中，recall 和 critical recall 均为 `1.0`；865 项回归通过 | 该 case 未认证视觉覆盖，因此 `precision=null`、`visual_recall=null`，不扩大为整份 PDF 全能准确率。[一期验收数据](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/86e1a26e6cc7c20abf7905fbddd3935ce6e41165/handoff.md#L32-L45) |
| 2026-08-20 表格对齐修复 | 112G/224G TP1a 表格对不上、插入行引起连锁错位、Figure 假表 | 13 张旧表全部映射到正确新表；`Table 30-12` 保留为唯一技术新增；1083 项全仓回归通过 | 最终状态仍是 `degraded`；表格强验收不等于整份 PDF 没有漏检。[表格强验收记录](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/5c4c8b3694e1c1b2e2a244ad2635d0e8ccbf8d08/handoff.md#L12-L33) |
| 2026-08-25 证据去重与配对恢复 | 表格重复染色、Figure 图注冒充正文、VMA/Module output 被拆成新增和删除 | 相关章节恢复为单个 `modified`；指定 Figure/表格噪声在 HTML 中为 0 次；1110 项回归通过 | 仍保留标题层级误识别和未配对章节的人工复核边界。[读者证据验收记录](https://github.com/ZhenlongYou/pdf-protocol-diff/blob/c4dbf83d2ad020eb85c7ff6251bbca668e76b84c/handoff.md#L12-L40) |

这些数字不能被简化为一个“总准确率”。它们的价值在于每个结论都绑定了特定文档对、特定事件、特定报告表面和精确代码快照；系统不再使用一个无法说明样本范围的百分比来遮蔽不确定性。

## 为什么这套方法比“换一个模型”更有效

文件对比的核心任务，是证明新旧两边的哪个对象是同一个对象、它内部哪些事实真正改变，以及哪些区域还没有足够证据。把两份 PDF 分别识别成大段文字，只完成了最前面的候选召回。更强的 OCR 或版面模型可以改善这一步，但缺少对象身份、坐标归属、失败关闭和真实语料验收时，它只会更快地生成一份看起来完整的错误报告。

这次改造的关键成果，是将“尽量配上”改成“证据足够才配”，将“一条都没找到”改成“明确说明为什么无法判断”，并将“报告卡片越多越好”改成“每个物理证据只由一个最合适的读者单元承载”。这才是识别效率真正提高的原因。

## 当前边界

- 复杂多栏、异常字体、表单、幻灯片、低质量扫描页和图形语义仍可能需要人工复核。
- 复杂公式的根号、堆叠分式、极限和矢量仍以原 PDF 截图为权威证据，工具不猜测一个结构化答案。
- 视觉哨兵能发现未解释像素变化，不能自动说明图形中的技术含义。
- 某一组真实 OIF 文档对验收通过，只证明该样本和已覆盖缺陷边界；不能直接推广到所有 PDF 版型。
- 若要单独评估“运行速度”，还需要在同一机器、同一 PDF 快照、同一页窗、同一 OCR/版面设置下，分别记录旧版和新版的端到端耗时与峰值内存。
