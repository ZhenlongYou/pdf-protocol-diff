# PDF 协议差异算法原理说明书

## 1. 目标

目标是回答“两个 PDF 在语义上哪里不同”，而不是比较二进制字节。PDF 页面本质是
文字片段、坐标、字体和绘图指令的集合；因此算法采用多阶段证据链：

\[
\text{页面抽取}\rightarrow\text{文本归一化}\rightarrow\text{章节定位}\rightarrow
\text{序列对齐}\rightarrow\text{prose diff}\rightarrow\text{表格/版式证据}.
\]

主结论来自段落文本，表格和坐标只作补充证据；否则一个换行或页眉变化会被误报成
协议条款变化。

## 2. 文本归一化

原始抽取得到 token 序列 (A=(a_1,\ldots,a_m))、(B=(b_1,\ldots,b_n))。归一化
包括 Unicode 空白统一、连字符断行合并、页眉页脚剔除、大小写/标点策略和单位保护。
数字、版本号、条款号、`shall/must` 等规范词不能被过度清洗。

## 3. 序列对齐

对 token 序列，LCS 可用于说明全局序列对齐原理；当前工程的主路径则使用
matching-block 风格的 `SequenceMatcher`，二者不是同一算法。LCS 递推为：

\[
L(i,j)=\begin{cases}
L(i-1,j-1)+1,&a_i=b_j\\
\max[L(i-1,j),L(i,j-1)],&a_i\ne b_j.
\end{cases}
\]

匹配块形成 equal，未匹配块分别形成 insert/delete/replace。代价函数可对数字和规范
词加权，使“0.5 UI→0.6 UI”不会与普通标点换行同权。复杂度一般为 (O(mn))，长
标准文档应先按章节/段落分块。

matching-block 相似比 \(R=2M/(m+n)\) 和归一化编辑相似度
\(s_{edit}=1-D(m,n)/\max(m,n)\) 都要对空输入单独定义：

- 双空序列返回兼容数值 1，但状态是 `BOTH_EMPTY_NO_EVIDENCE`，不能参与“有内容的相同条款”配对；
- 单侧为空时返回 0，状态是 `ONE_SIDED_EMPTY`，进入插入或删除语义；
- 只有 \(m>0,n>0\) 时才直接计算上述分式。

移动候选若用 n-gram 集合的 Jaccard 分数，则双空集合应返回
`BOTH_EMPTY_FINGERPRINT/unavailable`，而不是伪造一个 1。这些状态使三个原本会出现
\(0/0\) 的分式都有唯一、可审计的失败语义。

## 4. 移动内容与表格

同一文本在不同章节出现时，局部 diff 会显示 delete+insert。算法用文本指纹或 token
相似度寻找 moved candidate，再保留原位置与新位置证据。表格识别只报告行列、单元格
和坐标置信度；无法可靠识别时必须标为 low-confidence，不能把 OCR 猜测写成条款。

## 5. 手算例子

A=`shall use 0.5 UI`，B=`shall use 0.6 UI`。LCS 是 `shall use UI`，所以 replace 的
核心 token 为 `0.5`→`0.6`。若归一化错误地把小数点拆散或删除数字，算法会失去最重要
的工程变化。

## 6. 失败语义和结论边界

扫描型 PDF、字体编码异常、双栏顺序、脚注、表格跨页和页面移动都可能让抽取失败。
必须同时显示抽取质量、章节定位质量和表格置信度。报告不是法律意见，也不能仅凭文本
相似度判断规范兼容性；最终解释仍需人工回看原页。

验证包括：人工标注的增删改、纯页眉变化、整段移动、表格数值变化、双栏 PDF、扫描
OCR 低置信度和中英文单位。源码追踪：`main.py`、`gui_app.py` 及报告模块。
