# 报告审阅队列与证据收敛

本轮针对用户提出的“保留新旧截图，但不应让用户重新在两份 PDF 间找差异”优化报告层，不改写比较、匹配或视觉哨兵的结论。

报告将正文、表格、未解释像素和未完成像素核对分别转换为可回跳的审阅事项。已检测到的正文/表格事实、需要人工解释的证据、以及没有完成核对的物理页原因使用三个状态；它们的原始计数继续留在 JSON 和折叠审计统计中，不相加为“技术变化”。默认只显示内容变化，读者可切换其余状态；本机“已阅/需跟进”标记不写回报告。

为减少首屏图片和控制项，视觉页证据默认折叠，区域按钮按页内相邻区带折叠，图片按需加载。区带仅是浏览导航层，未合并任何像素组件，更不表示一个技术事件。对短但风险高的正文变化，数值、符号、否定与规范性情态词会获得一页一侧的源图定位；普通短文字变化维持原有截图预算。

验收范围是报告阅读和证据可达性：每项必须保持原始 HTML 卡和 JSON 记录的链接，覆盖项必须保持中性状态，视觉详情默认收起但不删除。正文与表格的显示顺序、JSON 卡号、队列链接、Markdown 和 TXT 使用同一份编号；点击视觉或覆盖事项会先展开其祖先折叠区再定位。顶部只显示三类审阅动作数量，不把正文片段和表格行相加为统一“明细”数字。它不证明任意 PDF 的抽取、章节配对或图内语义识别准确率；覆盖清单仍可能要求人工核对。

可执行证据清单为 `docs/verification/review-queue-evidence.json`，它绑定六类冻结输入、独立期望检查、空队列突变 RED/GREEN，以及一次真实报告生成与重开。最终回执由交付记录补充。
